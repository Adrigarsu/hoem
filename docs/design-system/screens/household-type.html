Household settings: name and type

The "Details" section of household-settings and the type-change flow (FR-ACC-009, FR-HH-007, NFR-LEG-001). Prototype for #19, pending approval. Members (#26) and "How the household works" (#30, #31) are added later.

Flow: choose a type → warning → (Family only) family roles → saved. Every dialog is a native <dialog>; focus returns to the type select when it closes.

1 · Owner

Name and type are edited separately: "Save name" saves the name; choosing another type opens the warning at once, so the type never changes silently.

2 · Member (not owner)

Read-only. The disabled controls say why in text, not only by their colour.

3 · Warning before changing the type (FR-HH-007)

Opens as soon as the owner picks another type. "Keep Shared flat" closes it and puts the select back. For Family the primary button continues to the roles; for the other types it saves.

4 · Family roles (only when the new type is Family)

One row per member, without names until members can see each other's (#26): "You" and "Member 2, 3…" in the order they joined. You are pre-set as a parent and can change it; everyone else needs a role before "Change to Family" saves, and nothing is pre-chosen for them, so nobody becomes a parent by accident. Being an owner and being a parent are separate: an owner can be a relative, a member can be a parent. A family needs at least one parent.

4b · Family roles: a member without a role

Nothing is saved. Focus moves to the first select without a role; the error is linked to it. Without any parent, the error "A family needs at least one parent" is shown above the buttons.

5 · "Just me" with other members

Shown instead of the warning. "Just me" is for one person, so the type cannot change while others belong. Once #26 builds the Members section, a "Go to members" action is added.

6 · A family with a child under 14 (NFR-LEG-001)

Shown instead of the warning when the owner picks any type other than Family and a member is a minor. No names: the owner already knows who it is, and the dialog does not reveal ages.

7 · Saved

The select shows the new type and a success message under it is announced politely. No undo: the change is confirmed in the dialog, and changing back is another confirmed change.

Desktop (1440): content column of the shell, dialogs centred

Desktop is not designed for household settings: the content column (max 720 px) of the desktop shell, sections as Cards. Dialogs are centred modals, at most 440 px wide (dialog-width), on every width.
